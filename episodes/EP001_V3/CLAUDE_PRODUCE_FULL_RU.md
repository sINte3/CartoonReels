## Активация и границы

Выполняй производство, только если пользователь явно поручил выполнить весь EP001 V3 с лимитом **600 кредитов Kie** и разрешил перечисленные ниже операции. При таком поручении действует специальное пакетное разрешение вместо обычного правила `/generate` «одно OK — одна задача» **только для этого эпизода**. Глобальный skill не переписывай. Шаблонные `generation_authorized: false` означают отсутствие разрешения в опубликованном файле; прямое сообщение пользователя может активировать пакет, это надо записать в локальном журнале.

Лимит: не больше **600 кредитов новых расходов этого пакета**. Прежние 205 и 164 кредита V2 уже потрачены и не являются частью нового заказа. Не трать весь доступный баланс, не пополняй счёт, не включай автопополнение.

База: K0, K1, K2 — три изображения обычной `nano-banana-2`, 2K, 9:16, PNG; A и B — два видео основной `bytedance/seedance-2`, по 4 секунды, 720p, 9:16, **generate_audio=true**. Без других моделей и провайдеров. Максимальный дополнительный резерв: **две адресные повторные генерации изображений и одна адресная повторная видеогенерация**. Итого не более пяти отправок createTask для изображений и трёх для видео. Резерв не обязателен и не используется ради косметических мелочей.

По котировке 06.11: база 364; весь названный резерв 2×12 + 164; вместе 552 кредита. Остаток до 600 — запас, не отдельный заказ. 600 — инструкция исполнителю, не заявленная функция ограничения в API Kie.

3. Проверь существующие файлы и журналы именно `CartoonReels_EP001_V3_*`, чтобы не создавать повтор уже выполненной задачи. Прочие личные материалы не нужны.

5. Пересчитай базовый пакет и возможные исправления. Если неизбежная базовая стоимость выше 600, параметры не поддерживаются или цену нельзя установить — остановись до платных вызовов и назови причину. Перед каждым видео сверить реальное тело запроса с текущим plan.json: основная модель, duration числом 4, 720p, 9:16, generate_audio=true, проверенные first_frame_url и last_frame_url, без reference_*. ## Производство без подтверждения каждого шага

Качество промежуточных результатов оценивай самостоятельно по сценарию и критериям ниже. Показывай короткий прогресс, но не возвращайся за OK после каждого принятого кадра. Вопрос пользователю нужен только при внешнем блокере, превышении лимита, необходимости сменить замысел/модели или невозможности получить читаемый результат в пределах разрешённого резерва.

1. **K0:** исходный референс героя из plan.json, правильный SHA-256; clean.prompt. Герой узнаваем, самодоволен, указывает на кучку; весь хвост, метла, ноги и кучка видны. Это новая постановка, не изображение старого «стоп».
2. **K1:** принятый K0 и исходник личности. Та же комната/камера; пола кучка больше не закрывает, мордочка явно запылена; лицо и шерсть сохранены. Если это просто затемнённая сцена или маска, кадр не принимается.
3. **Только A:** K0 как first_frame_url, K1 как last_frame_url, без reference_*. Один взмах видимо поднимает пыль, пыль достигает героя, затем открываются чистый пол и грязная мордочка. Контроль не сводится к ffprobe или статусу success. Без читаемого A остальное не заказывать. Если конкретная причина исправима одной дополнительной видеопробой в пределах лимита, это можно сделать из разрешённого резерва; вслепую повторять нельзя.
4. Из принятого A выбери четырёхсекундный монтажный отрезок, нормализуй временную шкалу и извлеки его фактический последний кадр. Не подменяй его исходным K1.
5. **K2 только теперь:** реальный конец A первым референсом, K0 для пространства вторым, исходник личности третьим. Новая пыль на полу, хвост готовит ту же метлу, герой испуган и защищается двумя лапами. Так уменьшаем риск несовпадения с реально полученной шерстью и позой.
6. **B:** фактический конец A как первый кадр, принятый K2 как последний; те же видео-параметры и включённый звук. Один чих видимо возвращает часть пыли на пол; хвост готовит второй взмах; герой замечает угрозу и защищается. Второй залп не показывается.
7. **Монтаж:** два принятых плана по 4 секунды, 8 секунд всего. У B можно применить постоянное укрупнение 10% по подготовленному фильтру. Крупный скачок лица/пропорций этим не маскировать; оцени согласованность. Не вставляй между видео исходные PNG как будто они пиксельно совпадают с первым кадром.

Исправления из резерва — только для конкретного видимого дефекта этой истории. Удачный кадр не перегенерировать ради произвольного варианта. Не увеличивать счётчик попыток из-за ошибок опроса/скачивания: они не создают новой генерации. Подтверждённая неудачная генерация считается попыткой, даже если по правилам Kie за неё не списали кредиты.

## Надёжность одной задачи

Перед отправкой сохранить запись о намерении; после ответа немедленно записать taskId. Дальше только статус и скачивание по этому ID. Таймаут/500/непонятный ответ при createTask — остановить новые платные действия до выяснения, создалась ли задача. Не компенсировать неопределённость новой отправкой даже при наличии резерва. 401/402 и другие внешние проблемы сообщать явно; не переключать провайдера автоматически.

При техническом отказе инструмента **до выполнения** сначала установить, что API-запрос действительно не отправлялся; отсутствие taskId само по себе этого не доказывает. Проверять безопасные журналы и состояние. Не обходить реальный запрет инструмента; обычную ошибку команды исправлять только в разрешённом объёме.

Ссылки скачивания обновлять по существующей задаче. Видеогенерация может длиться дольше обычного: не обещать точное время или автоматическое уведомление без настроенного механизма. Не завершать производство одним сообщением «queued»; сохранять состояние и продолжать поддержанным способом ожидания/опроса.

## Звук и сборка

Нативный звук нужен в обоих видео: метла, пылевой «пф», один короткий чих и начало повторного шороха. Без слов, пения и фоновой музыки. Не создавать песню через Suno, не подключать платный аудиосервис.

В прежнем блоке скачивания карточки наличие аудио означало создание немой копии для теста. Здесь аудио ожидается: основной исходник и финальный монтаж должны сохранить его. Немая копия может быть только дополнительной, не заменой основного файла; наличие звука не считать ошибкой, которую надо автоматически исправить удалением дорожки.

После получения проверить наличие непустой аудиодорожки, длительность и синхронность с видимым действием. При доступном прослушивании проверить голоса/музыку/резкие скачки; не утверждать, что прослушал, если сделал только техническую проверку. Не добавлять пустую дорожку, чтобы формально отчитаться «со звуком».

Если уровни дорожек заметно отличаются, выровнять их локально, сохранив тихую паузу на реакции. Не усиливать комнатный фон до уровня пылевого хлопка и не допускать клиппинга.

При соединении сохранить 8 секунд: маленькие затухания аудио по обе стороны склейки допустимы, полный звуковой crossfade не должен сокращать видео или смещать события. Готовый [фильтр с аудио](assemble-with-audio.ffmpeg.txt) рассчитан на два видео с реальными аудиодорожками. Не использовать старую сборку с `-an`.

Если нативный звук не пригоден, сначала исправить монтажом и доступными разрешёнными локальными средствами, сохранив удачное видео. Если для исправления нужен новый платный сервис или решение вне пакета — остановиться и сообщить конкретную проблему. Не повторять хорошее видео ради звука автоматически. Если проблема аудио не устраняется локально и обоснованно требует новой видеогенерации, можно использовать только тот же единственный видеорезерв пакета, сообщив причину в прогрессе; если он уже использован — остановиться.
