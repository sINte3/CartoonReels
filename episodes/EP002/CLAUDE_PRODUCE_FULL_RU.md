# EP002 «Силач понарошку» — одно задание на весь выпуск со звуком

Версия 8 ноября 2026 года, Asia/Tashkent. Это готовый производственный пакет. Сам файл не разрешает расходы. Его можно исполнять после прямого сообщения пользователя, разрешающего **весь EP002 с общим лимитом 640 кредитов Kie** и перечисленными ниже попытками. Общее «продолжай» в подготовительном чате не подменять подтверждением неизвестного расхода.

## Объём одного поручения

- База: три изображения K0/K1/K2 обычной `nano-banana-2`, 2K, 9:16, PNG; два видео основной `bytedance/seedance-2`: A — **4 секунды**, B — **5 секунд**, 720p, 9:16, `generate_audio=true`, first+last frame.
- Резерв только для конкретных дефектов: максимум **две дополнительные картинки и одно дополнительное видео** того же плана с прежними параметрами. Итого не больше пяти image-create и трёх video-create, не больше восьми созданий задач за весь EP002. Даже подтверждённая бесплатная неудача считается попыткой; ошибки опроса/скачивания новой попыткой не являются.
- Общий расход EP002 не выше **640 кредитов**. Это инструкция исполнителю, не серверный лимит Kie. Прежний EP001 и его оставшийся резерв сюда не относятся.
- Использовать существующий `/generate`, ключ KIE_API_KEY и уже работающие способы отправки, опроса, загрузки и скачивания. Глобальный skill не переписывать, новый конвейер не устанавливать.
- После прямой активации пакет заменяет правило «одно OK — одна задача» только для EP002: промежуточные решения принимаешь самостоятельно, показываешь короткий прогресс, не спрашиваешь подтверждение каждого шага. Шаблонные `generation_authorized: false` описывают опубликованный план до разрешения; активацию запиши в локальном журнале, а не делай вид, что файл сам её дал.

По последним пользовательским отчётам: база **3×12 + 4×41 + 5×41 = 405**; весь названный резерв — **24 + максимум 205**; общий максимум перечисленных попыток — **634**. Это расчёт по прошлым ставкам, не свежий тариф и не обещание потратить весь резерв.

## Бесплатная проверка перед первым расходом

2. Проверь существующие `CartoonReels_EP002_*` файлы и журналы в `E:\Generations`, чтобы продолжить уже начатое. Не создавать EP002 повторно и не трогать задачи EP001. До выяснения неоднозначной прежней отправки все новые платные действия остановлены.
3. Бесплатным документированным способом узнай баланс. Прочитай текущие цены конкретных режимов: изображения 2K с 1/2/3 референсами; видео 720p, 4/5 секунд, включённый звук и first+last. Проверь реальные схемы Kie: обычная Nano Banana 2 и основная Seedance, duration числом, audio=true, без смешивания first/last с reference_*. Не подставлять Fast/Mini, другого провайдера или платный upscale.
4. Покажи свежий расчёт базы, доступного резерва и источники/время проверки. Если базовый пакет не помещается в 640, баланса не хватает, тариф неизвестен или параметры не поддерживаются — остановись до createTask и назови точную причину. Не проводить платный эксперимент для измерения цены. Если цена изменилась, но та же конфигурация и все оставшиеся обязательные операции помещаются в лимит, при активированном пакете второе подтверждение не нужно. Резерв используется лишь в пределах денег и счётчиков, даже если новые ставки не позволяют купить его целиком.

Не запрашивать/печатать ключи и не копировать `.env` в логи. Не пополнять счёт и не включать автопополнение. Другие эпизоды, модели, Suno, платные аудио/монтажные сервисы и социальная публикация в поручение не входят.

Перед каждой новой платной операцией учти уже фактически потраченное, невыясненные/зарезервированные списания, ожидаемую цену текущей операции и всех оставшихся обязательных материалов. Коррекция не должна лишить возможности закончить базовый пакет в 640. Неизвестное списание не считать нулём. Расхождение ожидаемой и фактической суммы сначала выяснить, остановив новые расходы.

При таймауте/500/неясном ответе createTask нельзя слать дубль или переходить к другому платному этапу. Отсутствие taskId само по себе не доказывает, что задача не создана. Возобновляй только после установления её судьбы. При известном taskId — только статус/скачивание той же задачи. Ссылку скачивания обновлять существующим проверенным способом. 401/402 сообщать явно. Не выдавать очередь за готовый ролик и не обещать автоматическое уведомление без реального механизма ожидания.

## Последовательность производства

1. **K0 — усилие.** Исходный эталон героя из plan.json, SHA-256 сверить. Один жёсткий снаряд с двумя грузами, обе лапы и хвост заранее удерживают разные места. Вся гантель и непрерывный хвост видны, задние лапы стоят за ней. Короткие передние лапы действительно достают перекладину за счёт позы, а не удлинения. Если это невозможно на изображении, не покупать видео.
2. **K1 — чужая сила.** Принятый K0 первым референсом, эталон личности вторым. Гантель низко над полом; хвост заметно поддерживает центр. Герой выпрямился, подбородок вверх, явно доволен собой. Оба передних хвата сохраняются, свободной лапой бицепс не изображается.
3. **Только A, 4 с.** K0 как first_frame_url, K1 как last_frame_url. Сперва видно усилие, затем помощь хвоста, потом самодовольство. Принять только если зритель видит настоящего помощника. Если хвост просто украшает самостоятельный подъём или вес меняет форму/парит, смысл не выполнен. Адресную коррекцию можно делать из одного общего видеорезерва; косметические переделки не нужны.
4. Из принятого A выделить ровно **96 кадров при 24 fps**, нормализовать временную шкалу и извлечь последний кадр выбранного отрезка. K1 не заменяет фактический конец видео. Если материала/движения для полноценного отрезка не хватает, не добивать его пустыми стоп-кадрами для формального отчёта.
5. **K2 только после A.** Реальный конец A первым референсом, K0 для исходного пола/геометрии вторым, эталон личности третьим. Гантель снова на полу, хвост уже отошёл. Герой в заметно более низком приседе с округлившимися плечами, смущён и удивлён. Это крупная смена силуэта после гордой позы, а не только другой прищур. Нормальные пропорции и оба хвата сохраняются.
6. **B, 5 с.** Первый кадр — фактический конец принятого A, последний — K2. Хвост расслабляет хват и явно отходит; после прекращения поддержки — короткое тяжёлое опускание с приседом; затем осознание. Если вес висит после отпускания или падает из-за раскрытия передних лап, причина не читается. Не принять по одному `success`. Видеорезерв общий для A/B, а не отдельный на каждый.
7. **Сборка.** Используй 96 принятых кадров A и 120 B: девять секунд и 216 кадров, 24 fps. Сохраняй весь предмет. **Не переносить автоматически 10-процентное укрупнение из EP001**: оно может обрезать грузы. Шерсть может быть перерисована, но крупный скачок позы/длины лап/формы предмета нельзя объяснить только текстурой. Не вставляй PNG между видео как будто он пиксельно совпадает с ними.

Изображения из резерва корректируй с указанием конкретного дефекта: короткие лапы не достают, неверный контакт, второй хвост, пропавший груз, неразличимые гордость/присед. Не заказывать случайные варианты. Если резерв исчерпан или качество не позволяет продолжить, сохранить удачное и остановиться с точным описанием проблемы, не выдавать непонятный гэг за принятый.

## Звук и локальная сборка

Основные файлы со звуком. Дыхание усилия, сдержанный скрип, один низкий удар о пол, тихая смущённая пауза. Без слов, песни, музыки или второго удара. Старое правило карточки «при появлении аудио сделать немую копию» не должно удалить нужное аудио из основного результата. Немая копия может быть только дополнительной.

До сборки проверить у каждого принятого клипа: 720×1280/24 fps, достаточное число кадров, непустую аудиодорожку, отсутствие ошибок полного декодирования. Не создавать пустой AAC для галочки. Нормализацию уровня выбирать по этим клипам: прошлое усиление B на 5 dB из EP001 сюда не переносится. Сохранить тишину реакции и запас по пику. Пригодность шумов требует прослушивания; если инструмент его не позволяет, прямо написать, что проверены только уровни и звук ожидает слуховой приёмки. Не угадывать отсутствие речи по спектрограмме и не покупать новую генерацию вслепую ради недоступного прослушивания.

Готов [фильтр сборки 4 + 5 секунд](assemble-with-audio.ffmpeg.txt), рассчитанный на проверенные клипы с реальными аудиодорожками. Он обрезает лишние граничные кадры, соединяет A/V и делает маленькие аудиозатухания без сокращения хронометража. Не использовать `-an` для основного файла. Padding аудио допустим только для маленького технического хвоста, а не подмены отсутствующего/короткого звука.

```powershell
# $clipA и $clipB — проверенные исходники, $filterPath — локальный фильтр из закреплённого commit.
$graph = Get-Content -LiteralPath $filterPath -Raw
ffmpeg -i $clipA -i $clipB -filter_complex $graph -map '[v]' -map '[aout]' -c:v libx264 -preset medium -crf 19 -pix_fmt yuv420p -r 24 -c:a aac -b:a 192k -ar 48000 -ac 2 -movflags +faststart $output720
if ($LASTEXITCODE -ne 0) { throw 'EP002 assembly failed; inspect the error before continuing.' }
```

Обычный 1080p экспорт можно получить локальным масштабированием принятого монтажа. Новая детализация и платный upscale не заявляются. Не обрезать важное действие ради ограничения файла или формального числа секунд.
