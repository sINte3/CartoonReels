## Ревизия 2 — 09.11.2026, после трёх отклонённых K1

Пакет уже идёт, потрачено **48**. K0 принят. K1, K1-retry1 и K1-retry2 отклонены: nano-banana-2 копировала высоту гантели из K0, и вес оставался на полу. Резерв изображений (2 из 2) использован, видео не заказывались. Подробности — `production/README.md`. Пользователь поручил продолжить тот же пакет в пределе **634 кредита, включая уже потраченные 48**:

> «Меняем C на режим только первого кадра: принятый K0, 5 секунд, 720p, 9:16, generate_audio=true. Поле last_frame_url полностью убрать. Отклонённые K1 оставить отклонёнными. Не помечать их принятыми ради обхода проверки. Новые K1 не создавать. Новый граф: принятый K0 → C → фактический конец C → K2 → D.»

Что меняется:

- **Граф:** принятый K0 → C (только первый кадр K0, 5 с) → фактический кадр 119 C → K2 → D (только первый кадр K2, 4 с). K1 исключён из графа: новые K1 не создаются, отклонённые остаются отклонёнными.
- **Тело C:** шесть полей, без `last_frame_url`. Используется новый промпт [`C-solo-lift-first-frame`](prompts/C-solo-lift-first-frame.prompt.en.txt). Конечного кадра нет, поэтому итог задаёт сам промпт: хвост один поднимает гантель примерно до колен и держит её до последнего кадра; под обоими блинами заметный просвет и отдельные тени; лапы остаются на ленте медали у подбородка. Прежний промпт `C-solo-lift` (first+last) больше не используется.
- **Журнал не начинается заново.** Сохраняются журнал, taskId, расход 48 и счётчики попыток, бюджет не обнуляется. Использовано 4 изображения из 5 (повторы 2 из 2) и 0 видео из 3. Остаётся одна генерация — K2, без повтора. Если K2 непригоден, остановиться до D.
- **Деньги:** обязательный остаток C 205 + K2 12 + D 164 = 381, итого 48 + 381 = 429. Один общий видеоповтор — для C **или** D, максимум 48 + 381 + 205 = **634**. Обязательный остаток после C — 176, после K2 — 164, после D — 0.
- **До расхода:** отдельный сухой прогон продолжения на копии реального журнала (четыре изображения уже использованы, C не зависит от K1, `last_frame_url` отсутствует, общий максимум 634). Затем бесплатная повторная проверка цены и баланса и запись ревизии в журнал.

**Приёмка C в ревизии 2:** хвост один явно поднимает гантель и удерживает её с заметным просветом над полом; обе лапы остаются на медали вдали от перекладины. Совпадение с отклонённым K1 не требуется.

## Что сделать целиком

Взять уже готовое начало **7 с** из plan.json, создать три изображения обычной `nano-banana-2`, 2K, 9:16, PNG и два видео основной `bytedance/seedance-2`: **C 5 с** (хвост один поднимает вес), **D 4 с** (медаль уже на хвосте, хозяин аплодирует). Видео 720p, 9:16, `generate_audio=true`. Соединить в историю **16 с / 384 кадра**, со звуком, отдать MP4 720p и обычную увеличенную копию 1080p.

Резерв только для конкретных исправимых дефектов: максимум две дополнительные картинки и одна дополнительная видеогенерация того же плана с прежними параметрами. Итого максимум **5 image-create + 3 video-create**, до восьми новых задач. По прежним ставкам 3×12 + 5×41 + 4×41 = 405; весь резерв 2×12 + 5×41 = 229; общий максимум **634**. Резерв не является обязательным заказом. Старый EP002 не перезапускать, его остаток сюда не переносить. Семь готовых секунд оплачивать повторно не нужно.

Это единое поручение без OK после каждого принятого кадра. Самостоятельно оценивать промежуточные результаты по критериям ниже и сообщать краткий прогресс. Новое согласование нужно только при выходе за перечень/лимит, смене замысла/модели или невозможности закончить в выделенном резерве. Глобальный `/generate` не переписывать.

2. Проверить существующие `CartoonReels_EP003_*` записи/результаты: если что-то уже отправлено, продолжать по журналу, не начинать пакет заново. При неопределённой отправке остановить все новые платные действия до выяснения.
3. Проверить SHA-256 готового начала, его 168 кадров/7 с и извлечённого кадра 167 по plan.json. Это **`deliverables/ep002/EP002_timing_7s_sound_720p.mp4`**, а не исходный 9-секундный мастер. Брать бинарные файлы из согласованного checkout/коммита с проверкой хеша, не сохранять PNG/MP4 через текстовый Out-File. Не применять прошлые GainA/GainB к началу повторно.
4. Бесплатно проверить текущий баланс и цены: обычная Nano Banana 2 2K с референсами, основная Seedance 720p, 5/4 с со звуком, C first+last frame, D **только first frame**. Проверить поддержку всех режимов до первого оплачиваемого изображения. Схемы C/D различаются: у D не должно быть last_frame_url, даже null. First/last не смешивать с reference_*.
5. Дать краткий свежий расчёт. Если базовая стоимость выше 634, средств не хватает, цена неизвестна или режимы не подтверждены — остановиться до createTask и сообщить точный блокер. Если тариф изменился, но та же конфигурация и все обязательные остаточные шаги помещаются в 634, в рамках поручения повторный OK не требуется; резерв покупается только в пределах денег и счётчиков.

План и промпты извлекать проверенным export-inputs из закреплённого git-коммита с сохранением байтов, включая конечный LF. Отличие Windows-autocrlf не является поводом менять согласованный текст или подменять хеш. Тело prompt должно точно совпадать с экспортированным файлом, без одностороннего Trim().

Последний опубликованный баланс относится к концу EP002, это не свежий баланс EP003. Новые средства и пополнение не предполагать. Ключ KIE_API_KEY использовать существующим способом из `~/.env`, значения не выводить и не публиковать. Другие модели/провайдеры, Suno, платные аудиосервисы, upscale и социальная публикация не входят в пакет.

## Производство и приёмка

1. **K0.** Первый референс — реальный конец готового начала; второй — исходный эталон личности. Один бар с теми же грузами на полу, один хвост уже держит центр. Обе передние лапы держат одну медаль у подбородка; между лапами и перекладиной большой видимый просвет. Если лапа всё ещё касается веса, кульминация заранее сломана — видео не заказывать.
2. **K1** (в ревизии 2 исключён: три попытки отклонены, новые не создаются). Принятый K0, реальный конец начала, эталон личности. Тот же хвост один удерживает низко поднятый вес, лапы всё ещё явно заняты медалью вдали от перекладины. Если выглядит, что вес держит другая часть тела или висит без поддержки, исправить из общего резерва до C.
3. **C, 5 с** (в ревизии 2 — только первый кадр K0; общий видеоповтор один на C или D). Один плавный самостоятельный подъём хвостом, затем удивление хозяина и взгляд на медаль. Лапы не участвуют ни мгновения. Принять только однозначную новую кульминацию. Не переносить старое решение «примем с оговорками, оставим резерв для финала»: сюжетный провал C блокирует K2/D. Одна адресная видеокоррекция доступна из общего резерва; если он не помогает, сохранить материал и остановиться.
4. Выделить 120 кадров принятого C при 24 fps, извлечь фактический последний кадр 119 тем же фильтром, что пойдёт в монтаж. K1 не заменяет реальный конец видео.
5. **K2.** Реальный конец C первым референсом, K0 для дизайна медали вторым, эталон личности третьим. После намеренной склейки вес на полу, та же медаль на том же непрерывном хвосте, обе лапы хозяина пусты и готовы хлопать. Медаль одна; если она осталась в лапах или на шее хозяина, развязка не выполнена. Не анимировать передачу: кадр сразу устанавливает завершённое награждение.
6. **D, 4 с, first-only.** Два небольших хлопка, смущённая улыбка хозяина и гордо поднятый награждённый хвост. Вес неподвижен на полу, медаль не исчезает и не меняет владельца. Не добавлять нового взмаха, падения или угрозы, обрывающих историю.
7. Соединить готовые 7 с + C 5 с + D 4 с. Оценить переходы как намеренные склейки: в C руки уже освобождены и хвост вновь готов поднимать; в D награждение уже состоялось. У начала C медаль показана в лапах, в D — на хвосте: предмет и причина его перехода читаются. Держать всю гантель и хвост в кадре. Не прятать крупный скачок лица/анатомии/геометрии под заявлением «перерисована шерсть».

Это первый цельный кандидат для релиза. Готовые EP001/EP002 — технические пробы; их отсутствие кульминации не считается приемлемым стандартом нового целого.

## Деньги, одна отправка и сохранение состояния

Перед каждым createTask учитывать факт, невыясненные/зарезервированные суммы, текущую операцию и все оставшиеся обязательные этапы. Коррекция не должна сделать завершение невозможным в 634. Перед отправкой сохранить намерение; после ответа сразу taskId, до первого опроса. Любые таймаут/5xx/неясный ответ — неизвестное состояние, не повод слать дубль или параллельно заказывать следующий этап. При известном ID только опрос/скачивание этой задачи. Ошибка скачивания не расходует новую попытку генерации.

Все решения accept/reject, причины адресных изменений, ожидаемые/фактические creditsConsumed, source commit, хеши и файлы записывать в отдельный журнал `E:\Generations\CartoonReels_EP003_*`. Подтверждённая неудачная генерация считается попыткой, даже если за неё не списали. Нельзя использовать свободный остаток денег для дополнительных неоговорённых изображений или второго видеоповтора. Расхождение ожидаемой суммы сначала выяснить, остановив новые расходы.

## Звук, экспорт и выдача

Готовое начало уже содержит обработанный звук; не применять старое усиление A +5/B −0,5 повторно. Новые C/D выравнивать по реальным событиям и запасу по пику, а не по старым числам. В C — лёгкий скрип/вдох, в D — два хлопка и тихое покачивание медали. Нет речи/музыки. У D вес уже на полу — второй удар не нужен.

Проверить аудиодорожки и прослушать там, где это доступно. Если исполнитель не может слушать, прямо отметить незавершённую слуховую приёмку, не выдавать спектрограмму за доказательство отсутствия слов/музыки. Не покупать новый звук или повторять хорошее видео вслепую из-за отсутствующего прослушивания. При подтверждённом дефекте сначала доступное локальное исправление; платный видеоповтор для реального неисправимого дефекта использует тот же единственный резерв.

Перед сборкой исходники должны полностью декодироваться, содержать достаточные кадры 168/120/96 при 24 fps и непустой звук. Основной результат H.264 + AAC 48 кГц стерео, faststart, **16,000 с / 384 кадра**. Граф рассчитан на проверенные 9:16-источники с реальным аудио; его apad закрывает лишь маленький технический хвост, а не подменяет отсутствующий звук. Сборку с `-an` не использовать. Обычный 1080p экспорт не добавляет новую детализацию.

Отдать пользователю готовые MP4 720p и 1080p, не только путь на ПК или большой ZIP; сохранить исходники/журнал. Итог по-русски: расходы по этапам, использованный резерв, видимые недостатки и реально выполненные проверки. Пометить «релизный кандидат», пока пользователь не просмотрел/прослушал целое.

В конце сохранить записи в `episodes/EP003/production/`, готовые MP4 в `deliverables/ep003/`, адаптированные скрипты в `tools/kie-executor/ep003/`. Перед коммитом проверить публикуемые файлы на ключи, не выводя значения. Подтянуть свежий origin/main, сохранить чужие изменения и отправить в main в рамках поручения пользователя на доставку проектных результатов через GitHub. Если локальный предохранитель требует отдельного действия владельца для push, сохранить коммит и сообщить это; генерации из-за блокировки push не повторять.
