Во всех трёх попытках гантель осталась на полу или оторвалась от него на неразличимые 10–15 px из 2752. Резерв изображений (2 из 2) исчерпан, допустимого локального исправления нет. Поэтому по правилу эпизода результат сохранён, проблема описана ниже.

Ссылки: K0 ← кадр 167 начала, исходный герой; K1 ← K0, кадр 167, герой. Правки повторов — `CartoonReels_EP003_K1-retry1_addendum.prompt.en.txt` и `…retry2…`, рядом журналы с причинами. Правка retry2 задавала проверяемые признаки: нижний край блинов выше верха задних лап, полоса пола и отдельные тени под блинами, гриф у колен. Модель всё равно скопировала высоту гантели из K0 (первого референса). Полные причины решений записаны в журнале (`accept`/`reject`).

**K0 принят.** Обе лапы у подбородка держат медаль, до перекладины большой просвет: лапы на уровне груди, гриф на уровне голени. Перекладины касается только хвост: он выходит из-за корпуса справа и перекинут через центр грифа. Гантель та же: слева один блин, справа два. Отклонение: синяя лента надета на шею, хотя промпт просил «не на шее». Лапы держат ленту у подбородка, медаль висит на груди. Стоп-критерий K0 («лапа касается веса») не нарушен. Риск для K2: лента может остаться на шее хозяина.

## Почему остановка, а не C

- Карточка для K1: «Тот же хвост один удерживает низко поднятый вес». Для C: «Принять только однозначную новую кульминацию».
- Урок EP001 V3: seedance с first+last тянет движение к конечному кадру. Если C заказать с любым из трёх K1, он закончится весом на полу или почти на полу, и подъём будет неоднозначным. Это вероятные 205 кр, а с видеорезервом 410, на заведомо непринимаемый результат.
- Проверено локальное исправление (поднять гантель в K1-retry2 без генерации). Разделение по насыщенности не отделяет металл блинов от пола и шерсти: тёплый свет окрашивает блины, блики пола малонасыщенны. Ручные маски на ключевом кадре дали бы ореолы и разрывы досок вокруг блинов. Отклонено.
- Тот же урок EP001 V3 предупреждал: позу действия хвоста nano-banana-2 не дала и с адресной правкой, такие движения лучше отдавать видео. Здесь повторилось то же.

## Что можно сделать дальше (решение пользователя или чата проекта)

Нужно изменить карточку: C без `last_frame_url`, тело с 6 полями. Это правка `Build-Body` и повтор сухого прогона. Расход в текущем пределе: 48 + C 205 + K2 12 + D 164 = 429; с видеорезервом на C — 634. Изображений уже 4 из 5, поэтому у K2 повтора не будет.
2. **Новые попытки K1 с другим порядком референсов,** например без K0 первым. Нужно отдельное разрешение на дополнительные изображения по 12 кр. Три попытки показали, что модель держит композицию первого референса.
