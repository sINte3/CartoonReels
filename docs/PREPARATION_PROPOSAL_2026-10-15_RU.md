Существующий GitHub-репозиторий — более новая информация, чем фраза handoff об отсутствии репозитория. Публичность/приватность по Git-read определить нельзя.

Официальная лицензия Remotion разрешает бесплатное, в том числе коммерческое, создание видео физическим лицам и компаниям до трёх сотрудников; для других организаций условия отличаются. Это применимо к движку, а не к лицензиям на музыку, изображения и сторонние материалы. Для личного старта предполагаем эту категорию, без покупки лицензии. У HyperFrames лицензия Apache-2.0; размещённые облачные сервисы, медиа и внешние генеративные API имеют собственные условия.

Сайты `www.remotion.dev` и `platform.minimax.io` при чтении через текущий прокси вернули 403. Лицензия Remotion проверена в официальном GitHub-репозитории, информация о пакетах — в npm. Текущие тарифы и состав плана MiniMax независимо не подтверждены. Различие M3.1-Flash как текстовой/кодовой модели и H3 как видеомодели берём из handoff, не выдавая его за проверку аккаунта.

## 2. Две схемы облачного хранения

### А. GitHub + уже используемое облачное хранилище файлов — рекомендую

- Использовать существующий `sINte3/CartoonReels` как основную версию документов и кода; проверить и при необходимости отдельно согласовать приватность. Не создавать второй репозиторий.
- Медиа хранить в приватной папке уже имеющегося Google Drive или аналогичного сервиса. На этом этапе это рекомендация: ни наличие свободного объёма, ни подключение к агенту не подтверждены.
- В Git хранить сценарии, решения, описания героев, исходный монтаж/код, lockfile, реестр материалов и отчёты расходов. Видео и тяжёлые исходники — отдельными файлами в медиа-хранилище.
- После подключения агент сохраняет файл, сверяет размер и SHA-256, фиксирует постоянный ID объекта. Временный URL генератора не является архивом. Для незаменимых оплаченных исходников нужна вторая восстанавливаемая копия/экспорт; простая синхронизация не защищает от удаления.
- Без подключения не начинать платное производство с единственной копией в рабочей сессии. Текстовую подготовку можно продолжать.

Преимущества: простая работа с телефона и другого устройства, понятная история текстов, не нужен отдельный сервер. Новые платежи за хранение могут быть нулевыми при свободной квоте существующего аккаунта; это надо проверить, а не предполагать безлимит.

### Б. GitHub + приватное S3-совместимое хранилище объектов

Код и документы остаются там же; медиа получают постоянные ключи объектов, контрольные суммы и правила резервирования. Подходит при росте объёма и автоматизации. Потребуются аккаунт, проверка тарифа, безопасный доступ и проверка загрузки/скачивания через облачную среду. Не рекомендую вводить эту дополнительную настройку до первого принятого выпуска. Аккаунт, платный ресурс и секреты сейчас не создавались.

Начальная оценка объёма: четыре ролика по 20 секунд при среднем потоке 12 Мбит/с — около 120 МБ финальных видео. С исходниками, версиями и звуком разумно сначала проверить доступность 2–5 ГБ; это оценка для небольшого 2D/гибридного теста, не измеренный расход. Дублированная резервная копия увеличивает требуемый объём.

Минимальные документы после выбора схемы: `README.md` — как продолжить; `PROJECT_STATE.md` — статус, принятые результаты, следующий шаг и бюджет; `DECISIONS.md` — утверждённые решения; `ideas/BANK.md` — сюжеты. Затем по мере необходимости `episodes/`, `characters/`, `finance/` и `tools/`. Реестр медиа достаточно начать с CSV: `asset_id, episode, filename, version, storage_key, bytes, sha256, source, rights_note`. Не создавать пустую платформу или базу данных.

Вычисления выполняются в Codex; GitHub хранит исходники, но сам не обеспечивает видеорендер. Снимок опубликованной облачной среды может сохранять подготовленные файлы и зависимости, но живые процессы не переживают восстановление. Это не замена постоянному архиву материалов. В каждой новой задаче использовать существующий checkout; отдельный Git worktree без прямого запроса не создавать.

## 3. Рабочий набор инструментов

**Основной путь:** Codex → собственные 2D-рисунки/риг → Remotion → MP4 → FFmpeg/ffprobe для технической проверки → выбранное постоянное хранилище.

Remotion предлагаю потому, что повторяемые герои, позы и сцены удобно оформляются в повторно используемые компоненты. Руки, корпус, глаза, хвост, маски и реквизит анимируются отдельно; выражение лица, перенос веса, подготовка к движению, контакт и паузы создают действие. Результат не должен состоять из перемещений цельной картинки. Программный риг потребует художественной настройки; он не даёт автоматически сложную 3D-актёрскую игру.

HyperFrames — полноценный запасной путь для HTML/SVG/CSS/GSAP-композиций с экспортом MP4. Не устанавливать и не поддерживать оба движка для одного монтажа без причины. Если короткая проба выбранного стиля покажет техническую проблему Remotion, сначала диагностировать её и затем решать о переходе, а не переписывать всё автоматически.

MiniMax и другие генеративные сервисы пока исключены из обязательных зависимостей. Если позже понадобится сложный органический план, выбрать один сервис по сцене и подтверждённой цене. Ключи вводятся только в защищённых настройках; тип доступа и тариф можно сообщить обычным текстом. Название установленной кодовой модели не доказывает наличие видео, музыки и нужной квоты.

Первый технический этап после выбора: создать минимальный проект с зафиксированными совместимыми версиями, добиться работающего браузера, проверить короткое движение хвоста с касанием щётки, получить короткий MP4 и полностью его декодировать. Этот тест входит в первичную настройку, а не считается отдельным готовым выпуском. Не покупать облачный рендер при первой ошибке локального браузера. Для начальных проверок достаточно одного-двух рабочих процессов.

Стартовый формат: 9:16, 1080×1920, 24 кадра/с, H.264/AAC, примерно 15–22 секунды на сюжет. Без обязательной речи и субтитров. Звуковые акценты синхронны действию; музыку подбирать при необходимости. Исходную запись CoComelon из пилота в новый выпуск не переносить.

Бытовая визуальная комедия для семейной и более широкой аудитории; юмор узнавания, без дошкольных обучающих элементов по умолчанию | Рисованная 2D-анимация: один выразительный силуэт, управляемая кривая хвоста, несколько поз, одна комната. | **Лифт с сюрпризом** | Два маленьких доставщика везут обычный предмет; на каждой остановке действует одно странное правило. Первый вариант даёт узнаваемого героя и два намерения внутри одного силуэта. В нём можно менять не только предмет, но и отношения: хвост мешает, спасает, обижается, учится сдерживаться; иногда ошибается сам герой. Риск однообразия надо контролировать. Первую шестёрку историй не строить на одинаковой схеме наказания героя. Pocket Trouble остаётся прошлым неутверждённым вариантом; здесь его не назначаем названием канала.

## 5. Десять сюжетов для «Хвост спешит помочь»

1. **Чисто!** Герой прячет бумажки под коврик. Хвост убирает по-настоящему и встряхивает коврик; тот опускается на голову шагнувшего вперёд героя. Хвост заботливо поправляет его как шляпу.
2. **Тихий перекус.** Герой на цыпочках берёт одну ягоду. Хвост заботливо выкатывает рядом громоздкую сервировочную тележку и стул; на скрип герой застывает с ягодой у рта.
3. **Серьёзное фото.** Герой устраивает спокойный автопортрет. Штатив падает, герой хватается за ножку, хвост ловит и поворачивает штатив, возвращая камеру в ровное положение. На снимке вместо достойной позы — герой, повисший боком на ножке.
4. **Подарок.** Хвост помогает завязать бант и оказывается последней лентой. Герой торжественно несёт коробку и вынужден идти за нею боком.
5. **Один шарик.** Хвост спасает улетающую нитку, затем собирает ещё несколько шариков. Герой пытается ходить серьёзно, но едва касается пола.
6. **Подушка.** Хвост подкладывает себя под голову уставшему герою. Едва тот засыпает, рядом садится муха; хвост собирается её прихлопнуть, замирает и в последний момент выбирает беречь сон.
7. **Росток.** Герой бережно поливает цветок. Хвост ставит защитный зонтик, закрывая солнце; росток изгибается к свету, и зонтик превращается в ненужную тень над самим героем.
8. **Силач.** Герой гордо поднимает маленький груз, пока хвост незаметно держит тяжёлую полку. Герой замечает, кому на самом деле нужна помощь, и поддерживает хвост обеими руками.
9. **Мороженое.** Герой старается чинно дождаться своей порции, хвост принимает форму рожка. Продавец замечает его первым: хвост получает порцию, герой ревниво подставляет настоящий рожок.
10. **Воздушный змей.** Герой распутывает нитку. Хвост удерживает змея, расправляется как его пышное продолжение, и первая удачная попытка запуска превращается в смешную погоню героя за собственным хвостом.

Это банк сюжетов, не заказ на десять генераций. Первые четыре для проверки разнообразия: «Чисто!», «Подушка», «Подарок», «Силач». Здесь есть физическая комедия, забота, неловкость и взаимная помощь.

## 6. Первый выпуск: «Чисто!», 20 секунд

Цель героя — быстро закончить уборку. Препятствие — хвост действительно хочет всё убрать. Финальный результат — чистый пол и недовольный герой с ковриком на голове. Один герой, один фон, щётка, коврик, небольшой совок и несколько контрастных бумажек. Никакого текста в кадре не требуется. Актуальное постановочное задание: `/workspace/CartoonReels/episodes/EP001_BRIEF.md`.

| Время | Действие | Что зритель должен понять |
| --- | --- | --- |
| 0–2 с | Сразу видимое действие: герой последним взмахом заметает яркие бумажки под коврик. Гордо распрямляется; на коврике остался бугор | Он схитрил и думает, что закончил |
| 2–5 с | Кончик хвоста ощупывает бугор, поднимает угол; герой поспешно прижимает его ногой и невинно смотрит в сторону | Герой и хвост хотят разного |
| 5–10 с | Хвост перехватывает щётку и выметает бумажки в стоящий рядом совок. Герой отступает, освобождая место | Помощь становится слишком активной; мусор имеет видимое место назначения |
| 10–15 с | Хвост ставит щётку и встряхивает коврик, слегка подбросив для укладки. Герой делает шаг вперёд полюбоваться чистотой; коврик опускается ему на голову | Видна траектория предмета и причина физической шутки |
| 15–20 с | Хвост заботливо поправляет край, как у шляпы. Герой приподнимает край и медленно переводит взгляд на хвост. Короткая пауза | Законченная шутка и реакция |

Три контрольных вопроса после просмотра без звука: кто чего хотел, почему коврик оказался у героя на голове, что смешного в последнем кадре? На двух-трёх первых зрителях можно проверить понятность, но это не доказывает массовый спрос. Пользователь оценивает темп на телефоне; агент отдельно проверяет файлы и доступные кадры, не выдавая это за полноценное прослушивание.

Главный технический риск — касание хвостом предметов и читаемая траектория коврика. Сначала решить постановку в короткой бесплатной пробе. Коврику достаточно трёх форм: плоская, выгнутая в воздухе и свисающая с головы. Ранее предложенный рулон заменён более простой постановкой; не заказывать серии видео в надежде случайно получить правильную механику.

## 7. Месячный тест

Это четыре последовательные недели после выбора направления, не уже согласованный календарь публикаций. Даты зависят от темпа приёмки и доступных квот.

| Неделя | Результат | Условие перехода |
| --- | --- | --- |
| 1 | Выбор героя и хранения; документы; рабочая проверка браузера/экспорта; короткая проба движения; полный первый ролик | Герой узнаётся, контакт со щёткой читается, история понятна, итоговый MP4 технически исправен; пользователь принимает стиль |
| 2 | Второй ролик с другой эмоцией — «Подушка». После отдельного решения о публикации — выпуск принятого материала | Понятность и темп сохранены; нет необходимости заново изобретать героя |
| 3 | Третий ролик — «Подарок»; сопоставление доступных наблюдений | Зафиксированы фактические затраты и время, выбран один полезный вывод для следующего выпуска |
| 4 | Четвёртый ролик — «Силач»; предварительное решение о следующем месяце | Проверена повторяемость процесса. Последние 7-дневные показатели собираются уже после окончания четвёртой недели |

Для сравнимых первых тестов держать близкие длительность и стиль; не менять одновременно героя, технику, хронометраж и тему. Публикации и создание аккаунтов — отдельное решение пользователя. Если его нет, результат месяца — четыре принятых частных ролика и оценка процесса; данных о публичном спросе не будет.

После разрешённых публикаций собирать через 24 часа и 7 дней: охват/просмотры с точным названием поля площадки, среднее время просмотра, доступную долю досмотров, пересылки/сохранения, подписки, затраты и время выпуска. Не смешивать определения Reels и Shorts, органику и рекламу. Показатель времени просмотра делить на длительность только если смысл исходных полей это позволяет; повторные просмотры могут дать более 100%. Недоступный показатель помечать «нет данных», не заменять его догадкой.

Первичные управленческие критерии, предложенные до теста:

- Качество: сюжет объясним без речи; причинность действия и финальная реакция читаются; нет мешающих деформаций и грубых звуковых проблем.
- Производство: после настройки следующие два выпуска укладываются примерно в 2–5 часов работы над сценой каждый и до 30–45 минут участия пользователя на выпуск. Это цель для проверки, а не уже достигнутая скорость.
- Спрос: при достаточном объёме наблюдений посмотреть, достигают ли хотя бы два ролика среднего просмотра около 70% хронометража. Это внутренняя гипотеза для роликов 15–22 секунд, не норматив площадки и не доказательство прибыльности. Сопоставить её с пересылками и подписками.
- Если за семь дней у ролика менее примерно 500 просмотров или метрики недоступны, считать вывод о спросе слабым. Порог не делает выборку случайной или статистически репрезентативной; не объявлять ни успех, ни провал по одному такому ролику.
- Продолжать при сочетании приемлемого процесса и признаков интереса; при понятной, но скучной истории менять постановку/шутку. Высокие расходы и необходимость повторной ручной переделки каждого эпизода — повод упростить процесс, а не автоматически покупать более дорогую модель.

### Первый ролик отдельно

**Рекомендованный экономный вариант:** один 20-секундный выпуск, один герой и фон, программная анимация; $0 новым генеративным сервисам. Подготовка дизайна/рига ориентировочно 5–10 часов работы в сессиях; первый ролик ещё 3–6 часов. Исправление облачного браузера, ожидания квот и согласований могут увеличить календарный срок. Участие пользователя — ориентировочно 45–90 минут суммарно на выбор внешности и просмотр вариантов. Не предлагать новую подписку ради выполнения этой оценки.

**Если позже выбран гибрид:** предварительный предел первого выпуска $35: до $15 общий дизайн, до $10 одна нужная видеовставка, до $3 звук, $7 резерв. Эти $35 входят в месячные $90 и не прибавляются к ним. Дизайн повторно в каждом выпуске не оплачивать. Это распределение лимита: доступность нужного результата за него ещё надо подтвердить конкретной ценой.

До любого платного запуска составить короткий заказ: модель и endpoint, параметры, число изображений, заказанные секунды с учётом минимального шага, цена за единицу, включённая/платная квота, число разрешённых попыток, максимум с резервом. Если действующая цена не помещается в выделенную статью, сначала предложить изменение объёма или техники. При тайм-ауте искать исходную задачу по ID, не заказывать дубль. Резерв $20 не означает разрешение на неограниченные повторы. Пополнение и автоматический переход на pay-as-you-go не подразумеваются.

Ориентир работы на весь первый месяц: 16–30 часов в сессиях для экономного варианта, 20–40 для более подробной гибридной подготовки и контроля, без гарантии скорости внешних сервисов. Участие пользователя — примерно 2–4 часа и 3–5 часов соответственно. Это оценки, которые заменим фактом после первого ролика. Чтобы получить полную себестоимость, прибавить долю существующих подписок и стоимость времени; пользовательскую ставку сейчас не выдумываем. Доход первого месяца в окупаемость не закладываем.

## 9. Ближайшее решение и продолжение

Рекомендую утвердить направление «Хвост спешит помочь», схему А хранения и начать экономную 2D-пробу с нулевыми новыми внешними платежами. Это не утверждение, что новый герой уже понравится аудитории: первая цель — увидеть выразительное движение и понятную шутку, затем проверить повторяемость.

Выбор направления уже делегирован и выполнен; ограничение по времени со стороны пользователя не задано. Повторно спрашивать выбор из трёх концепций и доступные часы не нужно. Постоянное медиа-хранилище и точный тариф/квоты MiniMax остаются неизвестными; отсутствие MiniMax не блокирует подготовку. Секретные значения в чат не присылать. Предел новых расходов не увеличен.

Первоначальный маршрут после выбора: документы, хранение, выбранный движок, бесплатная техническая проба и оценка героя, затем полный первый выпуск. К настоящему моменту документы, Remotion-проект, лист поз и восьмисекундная проба готовы, рендер в текущей среде проверен. Инструкции установки и запуска сохранены в черновике настроек среды. Полный EP001, отдельный большой медиа-архив, публикации в соцсетях и проверка восстановления в новой задаче остаются следующими этапами.

Это предложение включено в подготовленный для передачи GitHub-проект по прямому разрешению пользователя. Состояние полного проекта описано в `PROJECT_STATE.md`; наличие этого файла не доказывает настройку отдельного медиа-архива или публикацию среды.
