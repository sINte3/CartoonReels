# CartoonReels — правила для Claude Code

Этот файл читает любая сессия Claude Code, открытая в репозитории. Сюжеты, карточки эпизодов и художественную оценку готовит отдельный чат проекта; его состояние — `PROJECT_STATE.md` и `DECISIONS.md`. Задача Claude Code — платные генерации по карточкам `episodes/<EP>/CLAUDE_*.md`, сборка и отчёт.

## Начало работы

1. `git pull`, затем прочитать `PROJECT_STATE.md` и карточку из сообщения пользователя. Карточку брать из checkout и записать commit в журнал пакета.
2. Проверить в `E:\Generations` уже существующие файлы и журналы этого эпизода: продолжать начатое, а не начинать заново.
3. Исполнять проверенным способом из [`tools/kie-executor/`](tools/kie-executor/README.md): скопировать папку прошлого эпизода, адаптировать, прогнать `dryrun` на моках до первого расхода.

## Деньги (Kie AI)

- Тратить только после прямого разрешения пользователя в чате, в пределах его лимита и перечня попыток. Карточка сама расходы не разрешает.
- Сначала бесплатно: свежие цены нужных режимов, включая звук, и баланс.
- Одна отправка `createTask` на попытку. Таймаут, 5xx или ответ без taskId означают, что задача могла создаться: остановить новые платные действия до выяснения, повторно не отправлять.
- Повтор — только после записанного отказа с конкретным дефектом и в пределах резерва.
- При приёмке следовать явным стоп-критериям эпизода. Неразличимую сюжетную причину нельзя принимать «с оговоркой» как косметическую неточность. Сначала проверить допустимое локальное исправление, затем конкретную коррекцию в общем резерве; если исправление в нём невозможно, сохранить результат и сообщить проблему. Успешный API-ответ, dryrun и ffprobe не означают художественную приёмку. Это не добавляет подтверждений каждого промежуточного шага внутри активированного пакета.
- Не менять модели и провайдера, не подключать Suno и платный звук, не пополнять счёт, не включать автопополнение, не тратить весь баланс.

## Ключи и публичность

- Репозиторий публичный. Ключи, `.env` и личные входные материалы не коммитить и не выводить в чат. Перед каждым коммитом проверять, что значений ключей из `~/.env` нет в файлах.
- `KIE_API_KEY` лежит в `~/.env` на ПК; скрипты читают его только в память процесса.

## Файлы

- Глобальный навык `/generate` на ПК сохраняет всё плоско в `E:\Generations` с логом рядом. Глобальный навык не переписывать.
- После пакета в репозиторий: текстовые записи — в `episodes/<EP>/production/` (с `.gitattributes` `* -text`), отчёт — в `production/README.md`, итоговые MP4 — в `deliverables/<ep>/`. Промежуточные PNG и MP4 остаются на ПК; в отчёте их SHA-256.
- Коммит и push — только по просьбе пользователя; по умолчанию в отдельную ветку.

## Уроки EP001 V3 (08.11.2026)

- Цены тогда: nano-banana-2, 2K, 9:16, PNG — 12 кр; seedance-2, 720p, 9:16, со звуком и first+last frame — 41 кр/с (4 с = 164), звук отдельно не тарифицируется. Перед каждым пакетом проверять заново.
- Seedance с first+last frame тянет движение к последнему кадру, а запреты в промпте («щётка не касается лица») выполняет ненадёжно. Ключевую позу закладывать в конечный кадр.
- nano-banana-2 превращает «пыль на лице» в ровную серую маску — описывать неровную порошковую пыль, сквозь которую видна шерсть. Позу «хвост заносит метлу» модель не дала и с адресной правкой: метла остаётся в покое. Такие движения лучше отдавать видео, а не опорному кадру.
- Громкость родного звука seedance между клипами разная (B был тише A на ~5 дБ): мерить `ebur128` и выравнивать по клипу до склейки, лимитер −1 dBFS.
- ffmpeg 9 на Windows: `drawtext` требует `fontfile=`, у Fontconfig нет конфига. PowerShell: массив из одного элемента возвращать через `, @(...)`; числа разбирать с `InvariantCulture`, в системе десятичная запятая.
- В отчёте отделять технические проверки (ffprobe, полное декодирование, громкость, порядок атомов) от просмотра и прослушивания. Не заявлять прослушивание, если его не было.
