## Выбранное решение

**Seedance 2.0 Standard, image-to-video, через fal.ai.** Первый тест — в браузерном Playground, без обязательного подключения API. После художественной приёмки имеет смысл автоматизировать задания из облака через API и сохранять результаты сразу после завершения.

Причины выбора: официальный источник fal документирует изображение как начальный кадр, 5-секундную длительность, 9:16, 720p, отдельный переключатель генерации звука и цену за секунду в долларах. Для первого теста это даёт проверяемые параметры и расчёт. Это выбор для нашей следующей пробы, а не доказательство превосходства модели во всех сценах: именно нашего героя, непрерывный хвост и контакт с метлой модель здесь ещё не анимировала.

## Конкретная первая задача

- Модель: `bytedance/seedance-2.0/image-to-video` (**не Fast**).
- Исходник: [оригинальный PNG](../lookdev-02/hero-3d-keyframe.png), 941×1672, 2 365 054 байта; без перерисовки или нового запроса изображения.
- Длительность: **5 секунд**, явно, не `auto`.
- Разрешение: **720p**, формат **9:16**. Ожидаемый вертикальный класс кадра — 720×1280; фактический размер проверяется в результате. Это не обещание исходного 1080p/2K. Финальный экспорт 1080×1920 не добавит отсутствующих деталей.
- Звук: **`generate_audio: false`**, не просто пожелание в промпте.
- Один непрерывный план, неподвижная камера, один герой, один хвост, одна метла.
- Хвост слегка наклоняет метлу; герой реагирует глазами и корпусом, поднимает лапу жестом «стоп» у груди; хвост замирает. Лапа не тянется к далёкой ручке.

[Промпт для копирования](prompt.en.txt). [Описание задания и параметры](job.json) — это подготовленный манифест, не готовое тело HTTP-запроса: URL изображения появится только после загрузки PNG на сервис. В этой подготовке изображение на fal не загружалось.

Новая подписка, покупка кредитов и бюджет на платный запуск не согласованы. Не обещаем, что $3,03 — минимальный платёж или автоматически обеспечиваемый провайдером предел списания.

Сначала одна задача. Вторая возможна только после разбора первой и отдельного согласования; пакет из четырёх сцен пока не заказывается.

## Порядок первой пробы

1. Открыть [страницу image-to-video модели](https://fal.ai/models/bytedance/seedance-2.0/image-to-video) в своём аккаунте fal.ai. Для этого шага API-ключ передавать ассистенту не требуется.
2. Загрузить оригинальный PNG. Выставить Standard, 5 секунд, 720p, 9:16, генерацию звука выключить. Названия интерфейсных элементов могут отличаться; ориентир — значения параметров, не выдуманные пункты меню.
3. Вставить промпт. До запуска проверить доступность режима и цену. Если цена отличается от расчёта, не считать её автоматически согласованной. Не включать автоматическое пополнение и дополнительные платные улучшения ради теста.
4. Только после разрешения на расход запустить одну задачу. Сохранить её ID; при долгом ожидании или ошибке загрузки работать с этим ID, не создавать замену автоматически. Фиксированный срок завершения не обещать.
5. Скачать исходный MP4 после успеха, сохранить параметры задания и фактическое списание, если оно доступно. Не полагаться на постоянство временного URL.
6. Проверить файл и реальную актёрскую игру. Если аудиодорожка всё же присутствует, удалить её локально без новой генерации.

## Приёмка и следующий производственный этап

Без звука читается причинная цепочка «хвост действует → герой замечает и останавливает жестом → хвост замирает». Проверяем выразительность глаз/корпуса/лапы, один непрерывный хвост, захват, опору ног и щетины, постоянство лица, света и шерсти. Простое покачивание всей картинки или движение камеры не проходят.

При анатомическом браке сначала определить причину. Не покупать цепочку случайных повторов; после двух осмысленных проб пересмотреть сложность движения или способ производства. Художественный результат этим ограничением не гарантируется.

После удачной пробы — короткий выпуск из отдельно поставленных сцен. **Remotion — монтаж, темп и звук; FFmpeg — проверка, немая копия при необходимости и экспорт.** Готовая картинка и успешный запрос API не означают художественную приёмку. Собственную 3D-модель и риг оценивать как отдельный следующий этап, если серия подтвердит ценность.
